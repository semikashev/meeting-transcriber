# Diarization

Diarizer modes, dual-track merging, speaker matching and tuning.

**Diarization:**
- `FluidDiarizer` uses FluidAudio (CoreML/ANE) for on-device speaker diarization — no HuggingFace token needed. Three modes: `.offline` (default), `.sortformer` (overlap-aware, up to 4 speakers, via `SortformerDiarizer`) and `.nemotron` (NVIDIA Nemotron 3, overlap-aware, up to 8 speakers, via `Nemotron3Diarizer`). Selected via `AppSettings.diarizerMode`; `DiarizerMode.speakerCap` bounds the speaker-count steppers. Both overlap-aware modes ignore `numSpeakers`: the models count speakers themselves.
- **Nemotron 3 mode** (`FluidDiarizer+Nemotron.swift`): the `fast128` preset (~200 MB, downloaded into FluidAudio's model cache on first use and loaded offline afterwards). The recording is fed through the streaming API in 60 s pieces rather than `processComplete`, which would hold the mel spectrogram of the whole file (about 180 MB per hour); the output probabilities are identical. The 10 ms frame probabilities go into a `DiarizerTimeline` (0.5 threshold, speech under 0.2 s dropped), so segments and embeddings take the same path as Sortformer mode. `Nemotron3Diarizer` carries stream state and is not thread-safe, so runs on one `FluidDiarizer` go through `nemotronRunGate`; model loads go through the process-wide `nemotronLoadGate`, because FluidAudio deletes a model folder without its version marker and a second first-time load would delete the first one's half-written download. The Nemotron 3 model itself is routed to CPU + Neural Engine, and so is the WeSpeaker embedding pass that follows, as in Sortformer mode: it loads with `FluidOfflineProcessor.computeUnits`, the units the offline pipeline and the live matcher use, rather than FluidAudio's default, which is `.all` outside CI and can route WeSpeaker through MPSGraph, whose abort takes the process down.
- **Dual-track diarization:** App and mic tracks are diarized separately, so a mode's speaker cap holds per track, and the expected speaker count goes to the app track only (the mic track auto-detects). Speaker IDs are prefixed (`R_` for remote/app, `M_` for mic/local), merged, and assigned via `assignSpeakersDualTrack`. Single-source recordings fall back to diarizing the mix with `assignSpeakers`.
- **Sortformer post-hoc embeddings:** `FluidDiarizer+SortformerEmbeddings.swift` extracts per-speaker WeSpeaker embeddings after Sortformer diarization (DiariZen-style hybrid), using overlap-excluded masks so mixed-speaker frames don't contaminate centroids. Enables `SpeakerMatcher` recognition when using the Sortformer mode, and the Nemotron 3 mode (an 8-speaker Sortformer) reuses it on its own timeline.
- `SpeakerMatcher` stores speakers in `speakers.json`. **The source of truth is a per-speaker sample history** (`StoredSpeaker.samples`, `VoiceSample`: embedding, date, speech length, track, recording, meeting title; up to 20 unpinned plus any pinned ones). The **centroid** (primary anchor, weighted mean of the samples with ≥ 3 s of speech) and the three **recent samples** (fallback anchors) are derived from it, so removing a sample or everything one recording taught (`removeSamples`, `removeContributions`) recomputes them exactly. A **pinned** sample is a reference voice: never evicted, always an anchor (enrollment pins by default). Entries written before the history load as `migrated` samples that derive the old centroid bit for bit, and a migrated-only history is not written, so untouched legacy entries round-trip byte-identically. Threshold 0.40, confidence margin 0.10. A label with under 10 s of speech gets no automatic name at all (`minSpeakingTimeForAutoName`, also kept out of the participant pre-match): short fragments crowd into one region of embedding space near many voices. A legacy entry (no history, no centroid) is matched against its samples alone until a confirmation of any length joins them; their mean is then its centroid, weighted by their number. An entry with only samples that cannot count (`awaitsQualifyingSample`, derived) never seeds one. An all-zero centroid counts as absent, and a centroid stored with a count of 0 as one sample; both came from earlier merges. An embedding with a NaN/Inf value is skipped and named in `ConfirmationOutcome.unusableVoice`, and a damaged `speakers.json` is copied aside before anything is written over it (`SpeakerMatcher+UnreadableDB`).
- **What reaches the DB is gated** (`SpeakerMatcher.sampleAdmission`): an embedding with < 3 s of speech, one within 0.15 of another person's anchor and no nearer to the named one, or one within 0.20 of samples of two or more other people (`hubSampleDistance`: fragments and noise crowd into one region near everyone) is not learned (a real DB had one bleed vector under eight names, blocking every match by the margin rule). Before that, `CrossTrackEmbeddingFilter` drops the copy of a person named on both tracks of one recording from the track with less speech (bleed), next to `EchoEmbeddingQuarantine` in `reapplySpeakerNames`. **Matching** takes labels longest speaker first and lets a name given on a track go to another label of the same track within 0.25 (the diarizer splits one voice into several clusters), never across tracks. `VoiceHealth` flags duplicate profiles, shared and outlier samples for Known Voices (Health column, Samples…, Clean Up…).
- **Measure matcher changes on real meetings, not synthetic vectors:** `SpeakerEmbeddingCorpusExtract` (env `MT_EMBEDDING_CORPUS_OUT`) dumps production diarization output per label; `SpeakerDatabaseReplay` (env `MT_REPLAY_CORPUS`, labels + confirmed names, kept local) replays meetings in date order through the matcher and write path. Numbers behind the rules above come from 50 meetings: precision 72 % → 84 %, known voices named 30 % → 61 %. Rejected there: centroid-only or bounded-sample scoring, AS-norm, per-speaker thresholds, CAM++ embeddings (FluidAudio beta; no better than WeSpeaker at equal precision).
- **Live speaker matching:** `LiveSpeakerMatcher` (actor) matches finalized live-caption utterances against `speakers.json` in real time, and on the EOU path also probes short windows for voice changes (`probe(audio:)`, see `transcription.md`), using the same WeSpeaker CoreML model as the batch pipeline — voices enrolled post-meeting are recognised in subsequent live sessions without re-enrollment. Cold-start optimisation: caches the WeSpeaker mask frame count in `UserDefaults` so only the embedding model is loaded on subsequent launches.
- **Experimental diarization tuning:** `AppSettings` exposes five `OfflineDiarizerConfig` knobs (`clusterThreshold`, `warmStartFa`, `warmStartFb`, `minSegmentDurationSeconds`, `excludeOverlap`) editable via Settings → Speakers → Experimental: Diarization Tuning. All default to FluidAudio community values; a reset button restores defaults.
- `DiarizationProvider` protocol enables mock injection in tests.
